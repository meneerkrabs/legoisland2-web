# z39ASB: Asteroid Belt (M3 port)

The mini-game on the way to Ogel (story node 62, zone table index 26, archive `z39ASB`, source file `Common\Z39ASB\c_src\GameLoop.c`): the player flies the shuttle through a belt of 235
asteroids, seen from the cockpit. The score starts at 10000 and drops with every hit (-2000) and every unit of fuel (hull) spent steering; the flight is won at the end of the course and
rewarded with a bronze / silver / gold trophy. It uses the generic loop template of the zones (docs/re/architecture.md 2.3, `src/shell/loopmachine.ts`) and the music / sound bank of z38PAR.
Addresses are VAs of the NL retail build; `FUN_` names are the Ghidra names of `decomp-le2/LE2.c`.

## 3. Gameplay

### 3.1 The state machine (node +0x18)

| state | meaning | ends |
|---|---|---|
| 0 | fly-in: the camera comes in from 400 units behind the shuttle, +4 per tick; the SHUT model is drawn | camera offset > -8 (after 99 ticks) -> 1, offset = -8 |
| 1 | **flight**: the cockpit (record HULL) is drawn, controls work, hull is used | a hit -> 2; hull < 0 -> 4; eye z > 8192 -> 5 (success) |
| 2 | hit: camera shakes for 30 ticks, no steering, no new hits | timer < 0: hits < 5 -> 1, else -> 3 |
| 3 / 4 | crashed (5 hits) / empty (hull used up): the camera pulls back 4 per tick | offset <= -400: var 0xfc = 2, state 6, result 2 (failure) |
| 5 | course flown: the camera pulls back; `FUN_007b7e9a(score)` ran on entry | offset <= -400: var 0xfc = 1, state 6, result 1 (success) |
| 6 | end (the loop leaves mode 2 in the same frame) | |

The shuttle moves on in z in **every** state (`z += speed` first thing in the update). Speed starts at 2.4 and grows by 0.01 per tick up to a maximum that follows the shuttle's z:
z <= 1024: 2.4 (asteroid spacing 20), <= 3072: 3.6 (16), <= 6144: 4.8 (14), above: 6.0 (12). A run takes 2442 ticks (81 s) when nothing is hit.

### 3.2 Controls and fuel

Keys (the 13-entry key table of the executable, logical bits): LEFT / RIGHT steer in x at 0.8 per tick, **UP goes down and DOWN goes up** (inverted flight stick; the help text
`CONTROL0 BUTTON_UP Omlaag gaan`, `CONTROL1 BUTTON_DOWN Omhoog gaan`, `CONTROL2 BUTTON_LEFT Naar links sturen`, `CONTROL3 BUTTON_RIGHT Naar rechts sturen`). LEFT wins over RIGHT, UP over DOWN.
A pad stick beyond +-0x14 of 512 steers proportionally (`axis / 128 * 0.8`); the port's input mapper turns the stick into key bits (full speed), the analog values are not used.
x is allowed while inside [-16, 16] on the side the shuttle moves away from, y inside [-12, 12]: the shuttle can overshoot the limit by one step. Every move of an axis costs **1.0 hull per tick**
(both axes in one tick: 2) and one score point per full hull unit (the integer shadow +0x288, `ftol(hull) < shadow`); a refused move costs nothing. Hull 1000.0 at the start; the move that takes it below 0 still happens (hull -1, score -1) and ends the run (state 4):
the hull is the fuel (the gauge icon is the Octan fuel logo).

### 3.3 Hit test (`FUN_007b7f68`)

Runs while the state is 1 or 2, before the movement. The reference point is the **camera position of the previous tick** (the camera struct is rewritten after the test), i.e. the shuttle at z - 8:
for every asteroid `dz = ast.z - eye.z`, `dx = eye.x - ast.x`, `dy = eye.y - ast.y`; only asteroids with `-4 < dz < 80`, `|dx| < 4.8` and `|dy| < 4.4` count.
* `dz >= 4` (still ahead): near-miss warning: one of the two whoosh sounds (`SND_ASB_MISS1/2`, 3D at the asteroid) and the alarm (`SND_ASB_ALARM`, `FINALALARM` after four hits: these two have no file in the data = silent). The warning ends (sounds stopped) in a tick without such an asteroid.
* `dz < 4` and no hit yet in this tick / not in state 2: **collision**: voice `OGSGAB06` or `07` (random), yell (`SND_ASB_YELL1/2`, table volume 0 = silent), impact (`SND_ASB_IMPACT1..3`), hit counter +1, the HUD icon `5 - hits` turns grey (tint 0xff7f7f7f: the first hit greys the top icon),
  score -2000 (min 0), state 2 with timer 30. The shake: the camera x offset runs +-0.16 (velocity +-1 per tick, flipped at the clamp, i.e. alternating every tick).

### 3.4 Asteroids (`FUN_007b9917`, `FUN_007b91b9`)

* 235 records named `ASTA` (`ASTA_1`..`ASTA_232`, `ASTB_1`, `ASTC_1` meshes), all with the same size (about 3.4 radius). Layout at construction, in record order, with `rand()` (MSVC LCG, `FUN_0085daf0`; `FUN_004388ae(r) = rand / 32767 * r`):
  rotation speeds `rand(2 deg) - 1 deg`, `rand(3 deg) - 1.5 deg`, `rand(4 deg) - 2 deg` per tick; every third asteroid (index % 3 == 0) drifts `rand(0.48) - 0.24` in x and `rand(0.4) - 0.2` in y per tick;
  x = `rand(60) - 26`, y = `rand(44) - 18`, z = the running accumulator which then grows by the spacing (first 40, afterwards the spacing of the regime of the asteroid's own z). This gives z = 0, 40, 60, 80, ... up to about 3870 with 235 asteroids.
* Each tick the asteroids with `-64 <= ast.z - eye.z <= 800` rotate and drift (matrix rebuilt from the Euler angles). An asteroid that fell behind (`dz < -64`) is put at the accumulator (new x / y, z = accumulator, accumulator += current spacing, new drift for every third) as long as the accumulator is below 8192:
  this is how the field continues to the end of the course (3870 -> 8192) with the spacing that belongs to the current speed regime.
* Only asteroids inside the same window are drawn (the draw hook sets / clears the frustum flag); in the intro (mode 1 / 9) the node does not run and all asteroids are drawn by the default draw.

### 3.5 Camera, shuttle and cockpit

Eye = (shuttle x, y, z + offset), target = eye + (0, 0, 1) (no roll, no pitch). Offset -400 -> -8 in the fly-in, -8 in flight, back to -400 at the end. **Field of view 0.3 rad** (`DAT_0089df2c`).
Models: record 1 `SHUT` (the whole shuttle, 28 long, seen from behind in the fly-in and the end) and record 2 `HULL` (the cockpit interior, 205 vertices): in states 1 and 2 the draw hook draws HULL at (shuttle x, y - 5.5, z - 22) scaled (1.3, 1.5, 1.2) instead of SHUT (both `FUN_0043a742`); in all other states SHUT is drawn and HULL hidden
(the original: `flags |= 3` on SHUT every tick, `|= 3` / `&= ~2` on HULL, the hook decides what is drawn; the port keeps those flags and, because its renderer draws every enabled record, sets `RF_NO_DRAW` (0x8000) on SHUT while HULL is shown; the asteroid window sets / clears the frustum bit `1` like `FUN_007b959c` plus `RF_NO_DRAW`). The cockpit therefore fills the screen below and to the sides; it moves with x / y of the shuttle. Records 3..11 (`SKY_` = `background.Msh`, `G000..G006` flashy stars / galaxy, `PCOL`) are never drawn as records.

**Backdrop** (`FUN_007b7c24` + `FUN_0088002d`, from the draw hook before the models): a quad at 1500 times the frustum unit plane (centre + forward, +-0.7 right / up, `FUN_00444370`), i.e. corners (+-1050, +-1050, 1500) around the eye;
vertex order bottom-left, bottom-right, top-right, top-left, indices (0 2 1, 0 3 2); texture = texture 14 of the zone (`text014.tga`, the nebula, wrapped), **uv = world (x, y) of the corner * 0.005**, so it scrolls with the shuttle's x / y and repeats every 200 units; render state block 1 (unlit, depth on), fog off.

### 3.6 HUD (`FUN_0046055f`, only in mode 2; DrawHUD.c on the 800x600 grid)

* 5 hit icons (Overlays texture 4, an asteroid), 60x60 at x = 20, slot i top y = 516 - 72 i (slot 0 at the bottom), white; the one that is hit turns grey (0xff7f7f7f).
* Score: `"%d"` of the score, Balloon24, yellow, centred at (400, 69).
* Hull gauge (`FUN_00460214(0x2dc, 0x2b8, 0x2cc)`): ratio `hull / 1000`; 12 segments 32x16 at x = 732, segment i top y = 492 - 16 i (bottom 4 red = texture 3, 4 yellow = 2, 4 green = 1), `trunc(12 r + 0.5)` of them lit; an arrow (texture 0, 32x32, x = 696) at `y = trunc(508 - 192 r) +- 16`; the frame icon (texture 5, the Octan logo, 60x60 at (716, 516)) flashes grey / white
  with `ftol(hull) & 0x10` below 150 hull and stays grey at 0.

### 3.7 End of the run, variables, story

* Failure (state 3 / 4 -> 6): var 0xfc = 2, result 2. The banner shows the score "0" (`DAT_05d5d528` is only written on success), the line `OGSGAB04` and speaks it; result menu page 19 (retry / abort); the story rewinds to the last hub.
* Success (state 5 -> 6): `FUN_007b7e9a(score)` ran when the course was crossed: **var 0x29 `SWITCH_GME_HISCORE_ASB`** = max(old, score); the comparisons are `score > 0x1b58` (7000) gold (var 0x102 = 2, var 0x44 = 2), `score > 0x1388` (5000) silver (var 0x102 = 1, var 0x44 = 1 when it was below 2), otherwise bronze (var 0x102 = 0, var 0x44 = 0 when it was below 1):
  bronze **< 5001 <= silver < 7001 <= gold**. Var 0xfc = 1, result 1. The banner (every frame of mode 4) then raises **var 0x44 `SWITCH_GME_TROPHY_ASB`** to medal + 1 (bronze 1, silver 2, gold 3) when it is lower: the trophy is only ever raised.
  Banner: the score at (320, 100), the STD.str medal text (`SGBRONZE` / `SGSILVER` / `SGGOLD`) at (320, 150), the line `OGSGAB03` / `02` / `01` at (320, 200) (also spoken); result menu page 16 (continue / retry). Continue = exit 2 -> `story.miniGameExit(true, true)` -> node 63 (z40aPO).
* Scratch variables of the zone: 0xfc (result, 0 / 1 / 2), 0x102 (medal index), 0xfd / 0xff / 0xfb = 0 and 0x100 / 0x101 / 0x103 / 0xfa / 0xfe = 1 (`FUN_007b7e00`, written by the constructor; nothing else reads them).
* Max score with no hit and no steering would be 10000; a perfect-ish run is 9900-9950, gold needs at most one hit.

## 4. Sounds, speech, music

Sound table ids (the table of the executable, `SND_ASB_*`): MISS1 0x1ca, MISS2 0x1cb (3D, near-miss whooshes), IMPACT3 0x1cc, IMPACT2 0x1cd, IMPACT1 0x1ce (`impacts[rand % 3]` = IMPACT1, 2, 3), ENGINE 0x1fe + ENGINE_IDLE 0x24f (loops, played every frame of the zone),
THRUST 0x24d (loop, pitch `22050 + spool (0..22050, +245 per tick) - drop (0..4050, +270 while steering, -200 otherwise)`), GYRO 0x250 (loop while flying, pitch `22050 + 0..2950`, +98 / -98 per tick, stopped when the thrust spools down), ENGINE_STOP 0x36d (state 3 / 4 / 5),
YELL1 0x202 / YELL2 0x201 (table volume 0), ALARM 0x203 / FINALALARM 0x204 / AMBIENCE 0x200 / THRUST_START 0x1ff (path `UNDEFINED`: no file, silent). Speech (`OG/Data/asb.str`, voice numbers 1699..1711): intro `OGSGAB13` (1711), hit `OGSGAB06` / `07`, banner `OGSGAB04` (fail), `03` / `02` / `01` (bronze / silver / gold); `OGSGAB05`, `08`..`12` (the Ogel scene) are unused here.
Music: `Z38PAR` (`Asteroids.sgt`, the same as z38PAR / z40aPO; started by the shell's `enterZone`), MIDI ambience `Asteroid` (`Asteroid_Amb.mid`, started by the game, stopped at the end).

## 5. Differences and approximations (nothing silently dropped)

* **Exhaust particles are not drawn**: the node creates three `rocket01.par` emitters on the shuttle matrix (`FUN_007b780c`: offsets (0, 4.08, 0), (+-1.44, 1.65, 0), additive sprites 0.9 -> 0.3, life 0.15 s) and switches them off in the end states. The port has no particle system yet (docs/re/rendering.md 8); in the cockpit view they are off-screen, they are only visible at the tail of the shuttle during the fly-in.
* **Music starts with the zone**, not when the loop leaves the help (`FUN_004432c0` in mode 9 -> 2): the shell's `enterZone` starts `Z38PAR` at zone entry for every zone.
* **Controller rumble** (`FUN_00438518(0, 100, 100)` while the camera shakes) is not ported; the analog stick values are not used (the port's input mapper only has direction bits).
* The roll accumulators (+0x2a8 / +0x2ac / +0x2b4) are kept but nothing reads them (in the original they are passed to `FUN_007b7c24`, which ignores its arguments); the Euler decay of the shuttle record (2 degrees per tick towards 0) is skipped because nothing ever sets those angles; the thrust glow (+0x2d0, +-0.05 per tick towards "steering") is kept (it probably feeds the exhaust particles, which are not drawn).
* The random source: the original uses the C `rand()` (seeding not found: probably `srand(time)`), the port a time-seeded MSVC LCG (`MsvcRand`); the *random* sound choices use `rand() & 1` instead of the original's `ftol(rand-ish * tick) & 1`. Same distributions, not the same sequence.
* A Codex review of `belt.ts` against the decompile (five findings: SHUT flags, the unused tilt accumulator, float32 rounding of the asteroid angles, the frustum bit, the tick-scaled random choices) was applied except the last point (the original scales `rand()` by the elapsed milliseconds before taking the parity / modulo; the port uses `rand()` directly: a different random sequence, the same distribution).
* A restart (pause menu / result menu) re-runs the whole zone (new layout, fresh records) instead of resetting the records with `FUN_007b9b50` + `FUN_007b70a1(0)`: equivalent.
* The loop's draw of the intro (mode 1) shows the scene behind the panel only through the generic runner (opaque panel), as for all zones.
* Test aids that are not in the original: **F9** finishes the course (the shuttle is moved to the finish line, the normal success path runs with the score it has) and **F10** empties the hull (normal failure path); both only act while the shuttle is under control.
